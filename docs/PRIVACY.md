# Privacy and Data Handling

This project uses fully synthetic data created for educational and portfolio purposes. It does
not use employer data, patient information, protected health information, or confidential
business information.

## How the data was produced

Every record was generated by `src/generate_sources.py` using Python with a fixed random seed
(77). The appeal identifiers, payer names, team names, dates, and status values are invented.
The organization name Lone Star Care Operations is fictional and is not intended to refer to
any real entity.

The three source extracts and the inconsistencies between them were designed by hand to
represent common governance failure patterns — differing date definitions, free-text status
vocabularies, stale manual extracts, duplicated reopened cases, and hand-edited workbook
values. They are illustrative of patterns, not derived from any real system.

`data/raw/_ground_truth.csv` is a generator artifact included so a reader can verify the
reconciliation logic. It is never read by the pipeline. In a real engagement no such file
exists.

## What this repository does not contain

- No patient names, identifiers, dates of birth, addresses, or clinical detail
- No employer data, internal documents, or configuration
- No real payer, provider, or vendor names
- No credentials, connection strings, or environment files

## Safe-portfolio practices followed

- Synthetic generation only; no anonymization or de-identification of real data, because no
  real data was involved
- Fictional organization and reference data
- No screenshots of real systems
- Findings described as modeled opportunity subject to validation, never as realized results
- `.gitignore` excludes database files, environment files, and temporary Office lock files

## If you are reusing this work

Do not substitute real operational data into these scripts and push the result. The privacy
posture of this repository depends entirely on the data being synthetic.
